# Awesome-lists PR prep (T-14)

Internal tracking doc — not linked from the public site. This is prep only: **no PRs, forks,
or issues have been opened against any external repo.** PyPI currently only has the old 0.2.0
single-tool release; the 9-adapter 0.3.x code shown in our docs isn't released yet, so a
reviewer clicking through right now would find a mismatch between the awesome-list blurb and
what `pip install token-finops-cli` actually gives them. Everything below becomes the
human's same-day checklist once v0.3.0 ships on PyPI and `qvest-ssels/burn-token-burn` is
public with matching docs.

Research performed 2026-09-14 by fetching each repo's live README/CONTRIBUTING via
`gh api repos/<owner>/<repo>/contents/...` (read-only, no clone/fork). All quoted entries and
rules below are verbatim from those fetches, not paraphrased.

## 1. QuesmaOrg/awesome-ai-tokenomics

- **Repo:** https://github.com/QuesmaOrg/awesome-ai-tokenomics
- **Status:** Active (pushed same day as this research). 175 stars, CC0-1.0, 1 open issue.
- **Section:** `## Monitor` → `### Dashboards` (matches the task description; confirmed still
  correct, anchor `#dashboards`).

### Existing format (verbatim, 1 example)

```
- [ccusage](https://github.com/ccusage/ccusage) - An open-source CLI that reads local agent logs to report token usage and cost across 15 coding-agent sources, with caching-aware pricing. ![tool: MIT](https://img.shields.io/badge/tool-MIT-blue?style=flat-square) ![last commit](https://img.shields.io/github/last-commit/ccusage/ccusage?style=flat-square&label=)
```

Pattern: `- [Name](url) - one-liner ending in a period. ![tool: LICENSE](badge) ![last commit](badge)`.
The last-commit badge is generated by their own `.github/workflows/staleness.yml`, not
hand-typed — but a submitted PR should still include the two badges so the entry isn't
missing them until the workflow next runs.

Ordering: **alphabetical** within the subsection.

### Drafted entry

```
- [token-finops-cli](https://github.com/qvest-ssels/burn-token-burn) - A stdlib-only CLI that reads local telemetry from 9 coding-agent tools (Claude Code, Codex, Copilot CLI, Gemini CLI, Aider, Continue.dev, Cline/Roo/Kilo, OpenCode, Hermes) to report budget runway, plus a local-vs-cloud savings estimator. ![tool: MIT](https://img.shields.io/badge/tool-MIT-blue?style=flat-square) ![last commit](https://img.shields.io/github/last-commit/qvest-ssels/burn-token-burn?style=flat-square&label=)
```

Placement: alphabetically after "OpenUsage" and before any entry starting later in the
alphabet (currently the last of the three sampled entries; verify full list order again at
submission time since new entries land continuously).

### Contribution rules (from CONTRIBUTING.md)

- Entries are not ranked by stars/downloads; each needs a primary source and (for
  cost/performance claims) a dated verification.
- Format strictly `- [Name](url) - one-liner.` — factual, not marketing copy.
- Process: open a PR with the entry; include the primary source URL.
- **Self-submission is explicitly allowed but gated:**
  - Must disclose self-submission in the PR body.
  - Every claim in the one-liner must be checkable against a public primary source (our repo
    code / docs) — no claim that only a hosted backend could confirm.
  - License badge must match the actual repo license (MIT — confirm this matches whatever we
    ship in `pyproject.toml` before submitting).
  - Project must be inspectable: working code, not a landing page.
  - **Needs at least one independent adoption signal** — unaffiliated users/projects
    referencing it, downloads beyond our own automation, or a third-party write-up. Star
    count alone does not satisfy this.
  - Near-identical submissions sent to many lists at once from the same account are
    **declined** — the reviewer checks the submitting account's PR history across GitHub.
  - Tools with no commit in >12 months get flagged/dropped.

### Submission-readiness verdict

**Blocked on two things beyond the PyPI release:**
1. v0.3.0 must actually be live on PyPI and the GitHub repo public with docs matching (the
   general PREP-ONLY gate).
2. **Independent adoption signal** — as of this research we have none (no external users,
   write-ups, or download data beyond our own). This is a real gate, not just paperwork; the
   human should line up at least one (a blog mention, a user issue/PR from someone outside the
   team, meaningful PyPI download numbers) before submitting, or the PR risks rejection on this
   basis alone.
3. Do not submit this and the other self-submission-sensitive list in the same sitting from the
   same account — their reviewers explicitly cross-check submission patterns across lists.

whichever comes first. Also: since this is an issue form and not a PR, T-14's "PR" framing
doesn't literally apply here — flag this to whoever executes T-14 so they don't try to open a

## Cross-list submission-order note

history across other awesome-lists and **decline near-identical submissions sent to many
lists at once**. Since four of these five drafted entries are near-identical one-liners for

Recommend spacing them by at least a few days, varying the description wording per list
(already done above — each drafted entry is phrased differently, not copy-pasted), and

`awesome-codex-cli`, `awesome-llm-token-optimization`) before the two gated ones
(`awesome-ai-tokenomics` needs an independent adoption signal; `awesome-claude-code` needs
14 days of age or 100 stars and uses an issue form, not a PR).
