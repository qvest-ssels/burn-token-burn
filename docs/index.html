$ token-finops

Read-only, local-first token usage and budget-runway tracker for AI coding agents — plus an honest local-vs-cloud savings estimator.

It reads the telemetry your coding agents already leave on disk and answers one question: at my current burn rate, does my budget last until the reset? Heterogeneous units are never summed — each tool gets its own runway, and the report tells you which one is the binding constraint, the one that runs out first. Everything is Python ≥ 3.10, standard library only, and it never writes to any tool's own data store.

source on GitHub token-finops-cli on PyPI

Install it

uv tool install token-finops-cli          # recommended
pipx install token-finops-cli
pip install token-finops-cli

The recording below is the real thing: a live pip install from PyPI into a throwaway virtualenv, and the token-finops entry point landing on $PATH. Every command and its output is real; the venv's path is the only thing sanitized, swapped for the generic /home/demo/… placeholder used elsewhere in this repo's fixtures instead of a real machine path.

Note what it shows honestly: PyPI currently serves 0.2.0, the original Copilot-only single-file tool. The 9-adapter CLI demonstrated in the recordings further down is 0.3.x and is not released yet — that is why this cast runs sessions --help rather than adapters.

What it looks like

Once you've wired the collect-statusline hook into ~/.claude/settings.json (see docs/INTEGRATIONS.md), report scoped to just that one tool is the fast path — no need to wade through every adapter the CLI happens to detect on your machine:

$ token-finops report --tool claude_code --compact
Claude Code        [############--------]  61.0%  runway   1.9h  WARN

Drop --tool to see every detected tool at once (Copilot, Codex, Gemini, …) with the binding constraint — the one that runs out first — called out; that's what the recordings below show.
