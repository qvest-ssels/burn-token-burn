$ token-finops

Read-only, local-first token usage and budget-runway tracker for AI coding agents — plus an honest local-vs-cloud savings estimator.

"Somebody burned the whole team's Copilot budget. Nobody could send a request for the rest of the month. (It wasn't me — but I couldn't have proven it.)"

token-finops grew out of token-finops-cli, a 600-line stdlib script that reads GitHub Copilot CLI's local telemetry and answers one question: at my current burn rate, does my monthly budget last until the reset? This repository generalises that "runway" idea to every coding agent that leaves telemetry on your disk, and adds the question people ask next: would a Mac Studio in the corner be cheaper?

Everything is Python ≥ 3.10, standard library only, and never writes to any tool's own data store.

It reads the telemetry your coding agents already leave on disk and tells you how long your budget lasts at your current burn rate.

  • Read-only — never writes to any tool's own data store
  • Offline by default — no network calls, no accounts, no API keys
  • Standard library only — Python ≥ 3.10, no runtime dependencies
  • Heterogeneous units are never summed — each tool gets its own runway, called out by its own name

Supported today: GitHub Copilot CLI, Claude Code, OpenAI Codex CLI, Gemini CLI, Hermes Agent, OpenCode/Kilo CLI, Cline/Roo/Kilo, Aider, Continue.dev — nine adapters, one per row in the adapter status table. Cursor, Windsurf and Ollama are reference-only for now (no local telemetry to read).

Usage-only tools get a runway too when you pass --allowance <USD per 30 days>.

Heterogeneous units are never summed. Each tool gets its own runway; the report tells you which one is the binding constraint — the one that runs out first.

$ token-finops report --compact
GitHub Copilot CLI [######--------------]  29.4%  runway  41.2d  OK
Claude Code        [############--------]  61.0%  runway   1.9h  WARN
OpenAI Codex CLI   [###-----------------]  17.0%  runway   3.4h  OK
Gemini CLI         [#-------------------]   6.1%  runway    inf  OK

binding constraint: Claude Code (5h) — runway 1.9h -> WARN

Install it

PyPI currently serves 0.2.0, the original Copilot-only single-file tool. The 9-adapter CLI below is 0.3.x and not tagged yet, so for now it installs from a checkout — once it's released, uv tool install token-finops-cli / pipx install token-finops-cli / pip install token-finops-cli will work directly against the package name. Four steps, install through your first report:

· ·

  1. 1 Install

    git clone https://github.com/qvest-ssels/burn-token-burn.git
cd burn-token-burn/token-finops-cli
uv tool install .                 # or: pipx install .   /   pip install .
    git clone https://github.com/qvest-ssels/burn-token-burn.git
cd burn-token-burn/token-finops-cli
uv tool install .                 # or: pipx install .   /   pip install .
    wsl --install                     # one-time, if WSL isn't set up yet
# then, inside your WSL Linux shell:
git clone https://github.com/qvest-ssels/burn-token-burn.git
cd burn-token-burn/token-finops-cli
uv tool install .                 # or: pipx install .   /   pip install .

    # installs the token-finops command

  2. 2 Verify it's on PATH

    token-finops --help

    # usage: token-finops [-h] {report,sessions,adapters,synth,self-audit,...}

    uv tool install and pipx install both put the command on PATH automatically; if a brand-new shell still can't find it, open a new terminal tab or run uv tool update-shell once.

    Same as macOS: uv tool update-shell (or a fresh shell) if command not found shows up right after install.

    Run this — and every step below — inside the WSL shell you installed from, not a native Windows terminal: PATH setup and the ~/.claude-style paths the adapters read both assume a Unix-style home directory.

  3. 3 See what it found

    token-finops adapters

    # tool found root # copilot yes ~/.copilot # claude_code yes ~/.claude # codex no ~/.codex

  4. 4 Run your first report

    token-finops report --compact

    # Claude Code [############--------] 61.0% runway 1.9h WARN

    One line per tool it found data for: a usage bar, a percentage, a runway (how long until you hit the limit at today's pace), and a status word. If more than one tool shows up, the binding constraint is whichever one runs out first.

Nothing found?

If token-finops adapters shows no data for any of your tools — you run something not on the supported list yet, or your tool simply hasn't written enough telemetry yet — you can still try the whole CLI on fake data in one command. See synth: it generates a complete, throwaway set of coding-agent telemetry so report, status and the rest have something real to read, without touching anything of yours.
