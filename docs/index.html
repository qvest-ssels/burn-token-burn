$ token-finops

It reads the telemetry your coding agents already leave on disk and tells you how long your budget lasts at your current burn rate.

  • Read-only — never writes to any tool's own data store
  • Offline by default — no network calls, no accounts, no API keys
  • Standard library only — Python ≥ 3.10, no runtime dependencies
  • Heterogeneous units are never summed — each tool gets its own runway, called out by its own name

Supported today: GitHub Copilot CLI, Claude Code, OpenAI Codex CLI, Gemini CLI, Hermes Agent, OpenCode/Kilo CLI, Cline/Roo/Kilo, Aider, Continue.dev — nine adapters, one per row in the adapter status table. Cursor, Windsurf and Ollama are reference-only for now (no local telemetry to read).

source on GitHub token-finops-cli on PyPI

Three commands, your own usage

No configuration. adapters tells you which of your coding agents it found; report --compact shows a runway per tool it found data for. Real output, from the CLI's own README:

$ token-finops adapters
  tool         found  root
  copilot      yes    ~/.copilot
  claude_code  yes    ~/.claude
  codex        no     ~/.codex
  gemini_cli   no     ~/.gemini
  hermes       no     ~/.hermes
  opencode     no     ~/.local/share/opencode
  cline        no     ~/.config/Code/User/globalStorage
  aider        no     ~
  continue     no     ~/.continue

$ token-finops report --compact
GitHub Copilot CLI [######--------------]  29.4%  runway  41.2d  OK
Claude Code        [############--------]  61.0%  runway   1.9h  WARN

binding constraint: Claude Code (5h) → runway 1.9h -> WARN

Two terms worth knowing before anything else: runway is how long until you hit the limit, at today's pace. Binding constraint is the one tool, of everything it tracks, that will stop you first — because units are never summed, this is the closest thing to a single number the report gives you.

Install it

token-finops-cli is not yet published to PyPI as the CLI shown above — PyPI currently serves 0.2.0, the original Copilot-only single-file tool. The 9-adapter 0.3.x CLI in this recording is install-from-checkout until it is tagged and released (tracked as T-05 in the repo's task list). Install from a checkout:

git clone https://github.com/tronicum/burn-token-burn.git
cd burn-token-burn/token-finops-cli

uv tool install .          # recommended — no separate venv to manage
pipx install .
python3 -m venv .venv && source .venv/bin/activate && pip install .

Once 0.3.0 is tagged, the same three tools will work directly against the package name (uv tool install token-finops-cli, pipx install token-finops-cli, pip install token-finops-cli) — full details, plus which coding-agent CLI each adapter needs installed, in docs/INSTALL.md.

The recording below is the real thing today: a live pip install token-finops-cli from PyPI, landing on 0.2.0.

Nothing found?

If token-finops adapters shows no data for any of your tools — you run something not on the supported list yet, or your tool simply hasn't written enough telemetry yet — you can still try the whole CLI on fake data in one command. See synth: it generates a complete, throwaway set of coding-agent telemetry so report, status and the rest have something real to read, without touching anything of yours.
